# 自动重修验证修复计划

目标：修复“附带公开测试，但模型写完即停、失败结果不反馈”的可控流程缺口。保留 v3/v4 原始源码、1/4 与 2/4 分数及全部费用。

1. 先以原失败交付复现，区分实际代码错误与工具／评分失败。
2. 公开测试执行与隐藏验收分开；公开回归只包含已披露缺陷，新保留集用于独立验收。
3. 每次交付最多三个模型回合，每回合最多六次提供方请求；相同失败源码不重复消耗预算。公开失败反馈给同一会话，包含真实诊断，不包含隐藏测试、参考实现或手工补丁。
4. 保存每次尝试、源代码哈希、公开结果、完整用量及文件守卫记录；预算用尽、无进展、工具／审计异常都保留为失败。完成运行与交付通过使用不同字段。
5. 固定四次交付（两题各基础／全开），显式检查最终真实源码，不允许人工修补或原分数覆盖；不能从小样本推断通用模型能力。
6. 回归覆盖公开失败后重修、一次通过、预算耗尽、无进展、回调异常和隐藏信息不进入反馈。真实 DeepSeek 请求复验后写收据和结果。

本轮不更换模型、不放宽文件守卫、不绕过审批，也不把测试提供给模型后的结果混入原盲测。
