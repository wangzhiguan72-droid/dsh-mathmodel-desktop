# 最新修复、有限自动重修与 0.1.5 交付

本轮范围：将任务能力选择、冻结和恢复及凭据安全修复纳入新的 Windows 安装候选；修复隔离评测中的请求预算中止处理；使用真实 DeepSeek 请求核验同批任务首轮与有限修复后的质量、成本。保留所有旧实验和 0.1.4 候选，不改个人配置，不公开发布。

## 根因与修复契约

v5 第四项的 requests=8 包含六个实际请求、两次发送前预算阻断。模型写入后继续读改，超过六次请求预算；评测器将这一已知中止作为整个实验的异常而退出。预算守卫没有实际发送第七个请求。

v6 保持每回合六次请求、每交付最多三轮、总请求最多 72 次、每响应 2048 tokens 的界限。已取消并等待结束、计量完整、固定文件完整的请求预算中止可作为失败尝试留存，运行真实公开测试后进入下一轮。它本身不能算成功，即使源码通过公开测试，也须下一轮正常结束并通过最终隐藏验收。超时、未结束的取消、缺计量和夹具篡改继续阻断。完整实验结束和交付全部通过使用不同字段。

新增回归先复现旧代码错误，再验证：预算中止不得直接成功、有限后续尝试可恢复、三轮耗尽仍失败，以及超时／计量／夹具异常不能伪装成可恢复中止。原公开反馈和隐藏隔离测试保留。

## 同批收益比较

实验固定为两个已知失败任务（CSV、依赖波次）各基础／全开一次，顺序事先由评测脚本确定。模型、初始源码、规格、公开及隐藏测试、输出预算保持一致。首轮源码在内存中保存；修复循环结束后才分别对首轮和最终源码运行隐藏测试，隐藏结果不进入模型反馈。首轮与最终交付均包括失败的分母，最终成本包括全部尝试。

这是“同一次运行中首轮交付 vs 最多三轮公开反馈”的描述性比较，不是随机分配的因果实验。只有两个独立题型；不证明通用质量优势、优于官方缓存，或 Fusion／联网／子代理的收益。费用为完整终止用量乘官方文档单价的估算，不是账户扣款账单。本轮北京时间周六，不进入工作日高峰窗口。

自动重修代码属于隔离评测器，不宣称桌面已获得对任意用户项目自动运行测试和修复的通用功能。

## 结果与交付收据

本轮真实运行完整结束，收据 `ok=true` 表示完整执行四项实验；`allDeliveriesPassed=false` 明确保留交付失败。30/30 实际请求具有完整终止用量，没有发送前预算阻断，也没有未归属请求。临时凭据已删除，Host 已退出。

| 指标 | 同批首轮 | 至多三轮公开反馈后 |
| --- | ---: | ---: |
| 完整交付通过 | 1/4 | 3/4 |
| 实际提供方请求 | 16 | 30 |
| 估算总费用，含失败 | ¥0.05863434 | ¥0.09591134 |
| 每次成功交付估算费用，含失败 | ¥0.05863434 | ¥0.03197045 |
| 平均耗时 | 22.759 秒 | 41.910 秒 |

两项由失败救回、零项退步、一项始终正确、一项始终失败。CSV 基础组在第三轮仍未通过公开及隐藏测试；CSV 全开组第二轮通过；依赖波次全开组第一轮、基础组第二轮通过。全部失败源码与诊断均保留，没有手工修补交付、改测试或继续加轮数直到成功。

结论：本轮样本中，有限公开反馈提高了交付成功数，降低了包含失败成本的每成功交付费用，但总费用增加约 ¥0.037277、平均耗时增加约 19.152 秒。不能宣称它降低每次任务费用、保证自动修复成功或普遍优于单轮。新流程对真实请求预算中止的恢复性质以回归测试证明；本轮真实调用没有自然触及该分支。
