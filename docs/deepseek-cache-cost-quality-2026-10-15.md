## 第三项：固定模型，比较两个能力组合

采用同一 Flash 模型、同一工作区、同一合成参考前缀。每组 5 次：首次观察、两次相同问题重复、两次变化尾部问题。组间顺序固定为基础组后全开组，没有随机交叉；首条请求不假定为冷缓存。全部请求完成，均未调用工具。

| --- | ---: | ---: |
| 模型可见工具数 | 34 | 46 |
| 出站工具 schema 哈希种类 | 1 | 1 |
| 5 次累计输入 tokens（含缓存） | 67,106 | 82,806 |
| 累计缓存读取 tokens | 53,376 | 65,792 |
| 加权缓存命中率 | 79.54% | 79.45% |

两组响应均报告 `deepseek-flash`。官方当前目录将该路由列为 DeepSeek-V4.1-Flash。每个请求都保留实际响应型号、原始 usage、工具/system/messages 哈希和时延；没有从哈希相同推断缓存命中。[官方型号与人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

本轮所有请求处于可确定的非高峰时段。Flash 每百万 tokens 的命中/未命中/输出报价分别为 **¥0.02 / ¥1 / ¥4**。官方 Messages 适配器的 inputTokens 为未缓存输入，与 cacheReadTokens、cacheWriteTokens 分开。本轮原始响应明确报告缓存写入为 0；不是把缺失字段当 0。费用按各桶分别计算，输出不再加一次 reasoning，属于文档价格估算，**不是账户扣款账单**。[价格来源](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

## 失败题与补测

去重题的原文为 `Return key values.`，严格预期属性名为 `values`。本表基础组返回 `result`，全开组返回 `key_values`；两者数组均为正确的 `[3,1,2,0]`。更早一轮基础组曾返回 `answer`。原题存在措辞歧义，因此保留各轮原始 4/5 结构评分，但不把它解释为模型计算能力下降。

在新的隔离工作区明确要求唯一属性 `values` 后，每组补测 1 次，**2/2 符合预期**。这批单独保存，不与原始评分合并，也不改写失败记录。新工作区路径和 system 前缀同时变化，因此它不是只有题面一个变量的因果实验。

补测中工具 schema 哈希仍与原组完全相同，system 哈希却变化。早期观察器记录的缓存读取占比约 **6.66% / 6.17%**，但缺少完整终止证据，只保留为初步观察，不作为正式计量结论。不能仅凭这两条请求认定缓存变化只由路径造成。官方缓存采用完整前缀复用与 best effort，不保证每个重复片段立即命中。[缓存规则](https://api-docs.deepseek.com/guides/kv_cache/)

补测证据：[收据](../dist/live-stage3-2026-10-15T15-29-03-134Z/receipt.json)、[摘要](../dist/live-stage3-2026-10-15T15-29-03-134Z/summary.json)。补测费用标为未知，未并入已验证费用小计；质量评分来自完整会话最终文本，仍保留 2/2 的观察。

## 审计修复与台账口径

早期异步 clone 观察器未可靠读取流结束信号，且固定等待存在把较晚记录划入下一试次的风险。已改为观察官方适配器实际消费的同一流：只有收到带最终输出用量的 message_delta、message_stop，以及四个合法 token 计数，才标记 auditVersion=2 / usageComplete=true。每轮边界等待所有在途审计记录落盘；中断、缺失计数或缺少终止事件均保留未知费用。报告汇总也拒绝把这些记录当作已验证缓存计量。

修复后重新执行第二项 6 次与第三项 10 次，**16/16 完整终止审计通过**。独立只读复核确认此前四项审计问题均已修复。旧的 20 个响应保留原收据与旧临时估算（legacy-provisional-summary.json）；重新生成的正式摘要将费用标为未知。7 次运行合计观察到 **36 个模型响应**，其中 16 个具备完整终止计量，官方价格估算小计 **¥0.05175424**；全部运行总费用未知，不把这个小计当作全部消费或账户扣款。[逐运行台账](../dist/live-benchmark-ledger.json)

## 当前结论与剩余范围

第二项已经有真实模型请求和工具执行证据。第三项首轮证明缓存实际发生、能力组合会改变出站工具目录和输入长度，且能够按真实 usage 计算费用；本轮基础组费用更少，但样本、顺序与缓存热度不足以支撑普遍降本、提速或质量优势。

第三项后续仍应补随机交叉、单变量工作区/时间前缀实验，以及使用隐藏测试的真实代码实现与建模任务。这一轮 JSON 小题不能替代那些质量验收；也没有拿它验证 Fusion 主副模型是否优于单模型。第四项权限与恢复负例没有提前开展。
