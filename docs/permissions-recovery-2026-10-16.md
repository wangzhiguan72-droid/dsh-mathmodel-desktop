## 凭据与连接恢复修复

凭据门面的读取、写入、清除、解析，以及写入／清除后的读取失败，统一公开固定安全错误。旧版连接直接操作凭据的路径也覆盖；带任意错误码的供应商异常不能绕过保护，服务自己生成的受信业务错误码仍保留。新增回归使用随机假秘密，检查 message、stack、JSON 和公开返回，不读取真实凭据。

最终审查发现的同类问题也已修复，并通过失败及成功路径回归：

- Grok 模型发现的 fetch、JSON、模型解析失败统一安全错误，HTTP status 限合法整数；服务自身生成的业务码仍保留。
- 旧配置 get 明确抛错时中止迁移，不调用 replace；缺省旧配置的新用户初始化行为保持。
- 删除连接并清除凭据时先清除成功，再删除连接。provider／store 清除失败保留连接供重试；设置保存失败也保留原连接及凭据引用，避免留下无法按 ID 重试清除的凭据。

随机假秘密、恶意 status、带 code 网络异常、Grok 假订阅令牌、清除失败再重试和迁移读取失败均有回归。独立只读复核确认这三处审查阻断闭合，未发现新的本轮阻断。
