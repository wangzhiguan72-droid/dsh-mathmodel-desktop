# Installed subscription image authorization gap (2026-10-11)

The installed MathModel profile loads `@deepseek-harness/dsh-mathmodel` 0.1.1, but does not load `dsh-plugin-subscriptions`. Its `package.json` has no such dependency, the profile's `node_modules` has no such package, and its old `patches/dsh-plugin-subscriptions@0.6.0.patch` is absent. The installed MathModel image code still obtains Codex and Grok sessions through `ctx.get('subscriptionSessions')`. A direct call to the installed Codex resolver with no service returns `subscription_service_unavailable`; see `dist/fusion-installed-verification/installed-subscription-probe.log` and `installed-environment-tests.json`.

The historical repository `数学建模/_repos/metamath-harness` contains a **local modification** for `dsh-plugin-subscriptions@0.6.0`: its token managers publish a Host-only `subscriptionSessions` service with `describe` and `resolve`, and its `registerImageTool: false` option prevents two global `image_generate` registrations. The service is not part of the unmodified package. The installed DSH rc.2 `@deepseek-ai/dsh-llm-pi-ai` package offers model routes and authorization flows, but its public exports are only `Config`, `PiAiAdapter`, `apply`, `inject`, `name`, `recordKeyFor`, and `supportedProtocols`; it does not expose the refreshed Codex/Grok access-token and Codex account-ID session required by MathModel's image adapters.

Therefore, the current profile cannot pass a real Codex/Grok subscription image call by changing MathModel's `resolveCodexSession` alone. Removing its fail-closed check or reading OAuth files directly would make a broken or unsafe claim of functionality. A working restoration needs a supported Host service that owns login, refresh, storage, and session snapshots, followed by a live authorization and image-call test. That entails introducing or maintaining a subscription provider package or a new OAuth implementation; neither is within this task's no-new-dependency constraint. No credentials were read, printed, or altered during this investigation.

The source tests intentionally assert a clear error when the service is absent. The eight legacy environment tests still test physical files and a patched 0.6.0 package that the current profile does not contain; their failure is retained as evidence, not hidden by creating placeholder files.
